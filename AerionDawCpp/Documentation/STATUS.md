# Aerion DAW Project Status — October 8, 2026 (v0.5.2 Alpha)

## Overview
**v0.5.2 Alpha** (notes: `Documentation/releases/v0.5.2.md`) adds three Milestone 6 features (track templates, which complete Project & Track Templates; MIDI learn for faders, pan and plugin parameters; a BS.1770 / EBU R128 loudness meter on the final output) and two fixes (a name chip when dragging from the Browser; the Inspector keeps the master selected). It replaces v0.5.1.1, which installed v0.5.1 builds could not see: their update check reads only three-part versions. It should be the first update to go through the in-app updater (0.5.1 to 0.5.2).

**v0.5.1 Alpha** is the first update meant to reach testers through the in-app updater. It fixes the master bus (plugins could be added but not removed), turns Follow Playback on by default and adds it to the Piano Roll, scans for new plugins at every start, and ships the first Milestone 6 features: sidechain routing, clip gain / normalise / reverse and project templates.

**v0.5.0 Alpha is the first public release** (October 8, 2026): the Milestone 5 app plus the first Milestone 6 work (the in-app update check, so later releases reach testers without a manual download), a user manual (`Aerion-DAW-Manual.html`, also under Help → User Manual), Follow Playback, a macOS build that behaves like a Mac app (menu bar at the top of the screen, Command shortcuts, the Mac Delete key, native title bar, trackpad gestures), an installer that waits for a running Aerion to close, a faster Piano Roll with large selections, and signing with the certificate kept in Keeper. A first v0.5.0 published on October 7 from an earlier commit was withdrawn and replaced by this one; that build calls itself 0.4.0 in its About dialog. Milestone targets from M6 on moved up one minor version (M6 is now v0.6.0). Aerion DAW closed **Milestone 5: Polish & Stability (v0.4.0)** on October 6, 2026. Milestones 1–5 — Editing, Mixing, Recording & Monitoring, Project & Workflow, and Polish & Stability — are complete. The last M5 session fixed a data-loss bug (plugin settings changed in a plugin's own window were not always saved), extended plugin crash protection on Windows to loading, saving and restoring a plugin's settings and opening its editor, moved plugin scanning into a child process, made the painted controls reachable by screen readers and the keyboard, measured the audio side (`AerionBench --audio`, all targets met), and finished the release workflow (installers named after the tag, macOS signing and notarization ready for when the certificates exist). Two items moved out of M5 because they are not code work in the repository: production code-signing certificates (blocked on purchase) and out-of-process plugin hosting (a large architectural change, scheduled after M6). The current focus is **Milestone 6: Complete Core (v0.6.0)**. CI builds and smoke-tests on **both Windows and macOS**; release packaging is a separate workflow; both are **manual (`workflow_dispatch`) only**.

## Recently shipped

### October 2026

**v0.5.3 Alpha (in progress; notes: `Documentation/releases/v0.5.3.md`):**

- **Plugin added or removed, other views stale (bug):** `AudioEngineManager::addPluginToTrack` and `removePlugin` did not call `broadcastChange()`, so only the view that made the change repainted; a plugin dropped on the master from the Browser appeared in the Inspector only after a click. Both now broadcast.
- **Blue frame on the Inspector fader after a click (bug):** the Inspector did not want keyboard focus, so JUCE gave a clicked Inspector's focus to its first focusable child, the fader's accessibility proxy, which draws the focus ring. `Inspector` now calls `setWantsKeyboardFocus (true)`, as `Mixer` does.
- **Export Mixdown froze while dragging the tail slider (bug):** each value change restarted the preview render, and `cancelPreview` joined the old render thread on the message thread (`EditRenderer::Handle` destructor), which can hang when the render needs the message thread (plugins). The tail slider now restarts the preview on release (`onDragEnd`); a replaced preview is cancelled without waiting and kept in `retiredPreviews` until `MixdownExportJob::hasFinished()` (set from the render's finished callback, which also runs after a cancel); a new preview waits until none is still running, so two renders of the live Edit never overlap. `cancelPreview` still blocks before an export and when the dialog closes.
- **Preview treated as an export (bug):** previews and exports share `MixdownExportDialog::exportFinished`, so every finished preview reset `exportJob` and showed "Rendered: <temp file>". A finished preview now only loads its waveform.
- Not yet tried in the app: the drop on the master, the BYP click, and dragging the tail slider with heavy plugins on the master.

**v0.5.2 Alpha (October 9):**

- **v0.5.1.1 was invisible to the updater:** installed v0.5.1 builds parse release tags as exactly three numbers (`Updates::Version::parse`) and skipped `v0.5.1.1` without a word; that build also called itself 0.5.1 (built from `7c3313e`, where CMake read only three numbers). Builds from 0.5.2 on read an optional fourth number (`Updates::Version::revision`; CMake accepts `x.y.z[.r]`) and log a tag they cannot read (`findUpdate`). `release-package` now starts with a `validate-tag` job that refuses anything but `vMAJOR.MINOR.PATCH[-suffix]` until no pre-0.5.2 build is in use.
- **Drag chip:** `Browser::makeDragChip` gives `startDragging` a small DPI-scaled chip with the plugin or file name instead of the default snapshot of the whole Browser component.
- **Master in the Inspector (bug):** `MainComponent::refreshFromEngine` reset the Inspector to the Timeline selection after every engine change; the master is never in that selection, so BYP on a master insert showed "(no selection)". It now keeps the master while the Inspector shows it and nothing is selected in the Timeline.
- **Track templates (M6, completes Project & Track Templates):** `AudioEngineManager::saveTrackAsTemplate` writes the track's state (a folder with its sub-tracks) as `<AerionTrackTemplate>` to `<prefs>/Templates/Tracks/*.aeriontrack`, without clips unless asked (`stripClipsFromXml`, shared with project templates), and drops a `sidechainSourceID` that points outside the template. `insertTrackTemplate` gives everything new IDs (`EditItemID::remapIDs`) and inserts after the selected track. UI: Save Track as Template... in the Timeline header and Mixer strip menus and the Track menu (`MainComponent::askTemplateName`, the dialog both kinds of template use), Track > Insert from Template.
- **MIDI learn (M6, MIDI Learn & Controller Mapping, first part):** Tracktion's `ParameterControlMappings` and `MidiLearnState` do the mapping. `learnParameter` turns learn on with a parameter pending (`ParameterChangeHandler::parameterChanged`); otherwise the last parameter touched while learn is on, including one moved in a plugin's own window, is mapped to the next controller moved. `MidiLearnWatcher` turns learn off after a mapping is added and writes the mappings into the Edit (`storeMidiMappings`, on each change rather than on save, because `saveToEdit` changes the Edit). UI: MIDI Learn submenu in the Mixer strip menu and on the Inspector fader, an "M" badge on mapped faders, Audio > MIDI Learn / MIDI Mappings... (`MidiMappingsWindow`), a LEARN pill in the toolbar. Not yet tried with a hardware controller or a parameter in a plugin's own window. User-level default mappings and control surfaces are still to do.
- **Loudness meter (M6, Analysis Metering, loudness part):** `Aerion::LoudnessAnalyser` (audio thread: K-weighting for any sample rate, 100 ms block energies into a lock-free FIFO, 4x true peak per BS.1770-4 Annex 2) and `Aerion::LoudnessMeter` (message thread: momentary, short-term, and integrated with the absolute and relative gates from a 0.1 LU histogram). It is fed by `Aerion::LoudnessTap`, Tracktion's global output processor: the final device output, after the master plugins and the master fader (Tracktion applies the master fader after the master plugin list, so a plugin there would measure pre-fader). First two output channels only; includes the click. Nothing is added to the Edit. View > Loudness Meter (`LoudnessWindow`, targets -14 / -16 / -23 / -24 LUFS) and short-term LUFS on the master strip. `LoudnessTests` check EBU Tech 3341-style sines (-23 and -33 LUFS, also at 44.1 kHz), gating and true peak; `AerionBench --audio` reports its cost (0.23 % of a 256-sample block, Release) and checks that it does not allocate.
- **Piano Roll playhead measured:** `AerionBench` reports "piano roll playhead move" (the two 4 px strips one display frame repaints). Release: 0.95 ms with the software renderer (3.1 ms Direct2D submission), against 5.6 ms for a full repaint and 0.11 ms for the Timeline's cached playhead; within budget, but the strip redraws the full height of notes and lanes. A cached layer like the Timeline's would fix it (`PERFORMANCE.md`).
- **Tests:** `AudioEngineTests` cover track templates (plugins, sends, a sidechain dropped, new IDs, folders) and MIDI mappings (pending parameter, driving, save and reload, clearing); `UpdateTests` cover four-part versions.

**v0.5.1 Alpha (October 8):**

- **Master bus inserts (bug):** plugins could be put on the master (FX button, Browser drop) but the master strip drew no insert column and the Inspector could not select it, so they could not be bypassed or removed. The master strip now has the same insert column as a track (`Mixer.h`, the `! isMaster` checks are gone, strip width is `kStripW + kInsertColW` for every strip). Clicking a strip calls `Mixer::onStripSelected`, which shows the track or master in the Inspector; for the master the Inspector hides input, arm, monitoring, freeze, quick filters and sends (`Inspector::isMasterSelected`). The master's context menu has **Bypass All Master Plugins**. Also fixed: a right-click on a Mixer insert slot opened the track menu (the popup check ran before the insert rows), so plugins could not be removed from the Mixer on any strip.
- **Follow Playback on by default (tester feedback):** the `followPlayback` setting now defaults to on (`kFollowPlaybackSettingKey`, `isFollowPlaybackOn` in `ViewShared.h`); a saved choice is kept. The Piano Roll draws a playhead and pages like `Timeline::followPlayhead` (`PianoRollEditor::updatePlayhead`, called from `MainComponent::onDisplayFrame`; a detached `PianoRollWindow` has its own `VBlankAttachment`). The playhead repaints a 4 px strip per moved pixel; not yet measured in `AerionBench`.
- **Plugin scan at startup:** `pluginScanOnStartup` defaults to on. `PluginDirectoryScanner` skips files already in the known list that haven't changed, so a start without new plugins only walks the folders. The splash shows `onScanProgress` ("Scanning plugins: <name>") while it is up and doesn't wait for the scan.
- **Clip gain, normalise, reverse (M6, Audio Clip Processing, first part):** an audio clip's right-click menu (`Timeline::showAudioClipContextMenu`) and a CLIP section in the Inspector (`Timeline::onClipSelected` → `Inspector::setSelectedClip`). Gain is `AudioClipBase::setGainDB`; normalise measures the peak of the source range the clip plays (`AudioEngineManager::measureClipPeak`, whole file for looped clips) and sets the gain for −0.1 dBFS; reverse is Tracktion's `setIsReversed` (renders a reversed copy). Clip thumbnails now always read the original file, and the Timeline draws a reversed clip's waveform from the mirrored range, flipped, scaled by the clip gain (capped at 4×). Gain envelope and pitch/speed wait for time-stretch.
- **Sidechain routing (M6):** **Sidechain Source** in the insert-slot menu of the Mixer and Inspector, for plugins where `Plugin::canSidechain()` (`ExternalPlugin` enables all buses, so a VST3/AU sidechain bus counts). `AudioEngineManager::setPluginSidechainSource` sets `sidechainSourceID` by track ID (Tracktion's name-based setter matches "N. name" strings) and calls `guessSidechainRouting` when the plugin has no wires. The slot shows "SC" (Inspector) or an accent letter (Mixer). Not yet tried with a real sidechain plugin.
- **Project templates (M6, project part):** **File → Save as Template…** (name, *Include clips*) writes an `.aerion` to `<prefs>/Templates` (`AudioEngineManager::saveProjectAsTemplate`; without clips, clip elements are stripped from the saved XML); **File → New from Template** lists them and opens one untitled (`MainComponent::openTemplate`), plus **Show Templates Folder**. The list is read when a menu opens.
- **Shortcuts in the macOS menu bar:** JUCE draws a key equivalent only for an item with a `commandManager`, taking the key mapped to the item's ID (`juce_MainMenu_mac.mm`). In the macOS menu bar `DAWMenuBar::hint` now appends a marker (`kActionMarker`) and the action ID instead of tab text; `SystemMenuBar::attachShortcuts` strips it, gives the item an app-wide command ID registered in its own `ApplicationCommandManager` with the keymap's current key (refreshed each time macOS asks for the menu, so rebinding shows), and keeps the item's menu-local ID working through `item.action`. Settings… in the application menu gets ⌘, the same way. A key press is not handled twice: JUCE's `performKeyEquivalent:` offers it to the focused component first and returns YES when Aerion used it, so the menu only gets keys nothing in Aerion took. `AerionBench --verify` checks the mapped keys, rebinding, that marked items still run their command, and the Settings key. Not yet seen on a Mac.
- **Quitting never waits on a plugin scan (found while testing the first update):** an update's installer starts after Aerion's shutdown, and the installer waits only 15 s for the program to close. `AudioEngineManager::stopScanThread` asks the scan thread to stop and waits 2 s; if it is still running it ends the scanner child process (`ScannerProcesses::endChildren`: toolhelp snapshot on Windows, `pkill -P` on macOS; Tracktion keeps the child out of reach) and waits 0.5 s more. If the thread still runs (a scan inside Aerion itself, such as an Audio Unit), `~AudioEngineManager` has saved its settings by then, runs `onForcedQuit` (starts a pending installer) and ends the process, because destroying a running `juce::Thread` waits for it and the engine cannot be freed under it. The settings, device state and recent projects are now saved before the scan thread is stopped. Not yet seen to matter on Windows: a VST3 scan polls its abort flag every 10 ms, so the forced path is expected mainly with macOS Audio Units.
- **Tests:** `AudioEngineTests` cover removing a master plugin, clip gain and reverse through save and reload, normalise (and a silent clip), a sidechain source through save and reload, templates with and without clips, and ending a child process. `UpdateTests` check that the version text reads the same everywhere.

**v0.5.0 Alpha (October 8), the first public release,** ships everything below down to the Milestone 5 close-out. Testing the update window without publishing anything: start a build with the environment variable `AERION_PRETEND_VERSION=0.4.0` and its update check acts as that version would, so it is offered the newest real release (the log says so).

- **Mac menu bar, title bar and trackpads (October 8, tester feedback):** the menus are built once (`DAWMenuBar::buildMenu` / `handleMenuResult`) and shown by the in-window bar on Windows and, on macOS, by `DAWMenuBar::SystemMenuBar` (a `MenuBarModel` given to `setMacMainMenu`; macOS rebuilds a menu each time it opens). On macOS the in-window bar is hidden, the application menu has About, Check for Updates… and Settings…, the File menu's Audio Settings and Help's About / Check for Updates are left out, and items carry no shortcut text (the macOS menu bar shows text after a tab literally; native ⌘ hints need an `ApplicationCommandManager`, not done yet). `app.settings` (⌘, / Ctrl+,) opens Audio Settings. The main window uses the native title bar on macOS. Timeline and Piano Roll read a trackpad's sideways swipe (`deltaX`), zoom with Ctrl / Cmd + wheel (`isCommandDown`, was the physical Control key on macOS) and with a pinch (`mouseMagnify`). `AerionBench --verify` checks the menu model (names, refresh, no shortcut text, items moved to the application menu, a click runs its action) and the trackpad handling; none of the macOS behaviour has been seen on a Mac yet.
- **Mac keyboard (October 7, tester feedback):** default shortcuts use `command` (Ctrl on Windows, Cmd on macOS) instead of `ctrl`, which on macOS was the physical Control key. On macOS, Delete Clip / Track and Delete Notes default to Backspace (the key labelled Delete on a Mac). Saved keymaps carry `version="2"`; on macOS a version 1 binding that still equals its old default moves to the new one (`AerionKeymap::keyFromSaved`), while bindings the user chose stay. Menu items take their shortcut text from the keymap (`AerionKeymap::menuText`: "Ctrl+Shift+Z" on Windows, JUCE's symbols on macOS), so a rebinding shows there too. The manual's Mac notes now match. Tests cover the Command defaults, the Mac conversion and the menu text.
- **Follow Playback (October 7, tester feedback):** **Transport → Follow Playback**, a toolbar button (`aerion_follow.svg`) and **F** (`transport.follow`, rebindable). Off by default and kept in user settings (`followPlayback`). While playing, `Timeline::followPlayhead` pages the view when the playhead leaves it, putting the playhead 5 % from the left; a jump out of view (playback started elsewhere, a loop going round) is followed too. A scroll by the user that leaves the playhead out of view is respected until the playhead is back in view or jumps. Pages go through `scrollTo`, so they reuse cached pixels. `AerionBench --verify` plays 40 s frame by frame and checks the playhead stays in view, a scroll away is kept, a jump is followed, and nothing moves when it is off.
- **Installer waits for Aerion to close (October 7):** installing over a running Aerion stopped with NSIS's "Error opening file for writing … Aerion DAW.exe", and the in-app updater would always hit it, because it starts the installer while Aerion shuts down. `Packaging/Windows/WaitForAerionToClose.nsh` (included through `CPACK_NSIS_EXTRA_PREINSTALL_COMMANDS` and `_UNINSTALL_COMMANDS`) checks whether `Aerion DAW.exe` can be opened for writing, waits up to 15 s, then asks the user to close Aerion (Retry / Cancel). Tested with a running copy of the exe: waits and installs once it closes; aborts (exit 2) if it never does.
- **Code-signing certificate from Keeper (October 7):** `release-package` fetches the Windows signing certificate (`.pfx` attachment and password) from a Keeper vault record through Keeper Secrets Manager (`Keeper-Security/ksm-action`), when the `KSM_CONFIG` secret and the `KEEPER_CODESIGN_RECORD` variable are set; the `WINDOWS_CERT_*` secrets remain the fallback. The certificate is opened and its subject, thumbprint and expiry logged before signing, and removed from the runner afterwards. Verified with a real run (a draft release of the Windows installer, since deleted): the certificate came from the vault record and both the application and the installer were signed and timestamped. The record must be a **Login** type (a File record has no Password field). The signing steps check the result with `Tools/Test-AerionSignature.ps1` (signed, unchanged, expected thumbprint, timestamped) instead of `signtool verify /pa`, which fails on a self-signed certificate because its root is not trusted; with a self-signed certificate the check passes with a warning, so the workflow does not fail.
- **AerionBench: Piano Roll and regression baselines (October 7):** the bench paints the Piano Roll with a dense clip (2000 notes, 1000 CC events) and `--verify` checks three of its partial repaints. `--save-baseline=<file>` keeps a run's timings, paint and `--audio`; `--compare=<file>` lists them against it and returns exit code 3 if any is more than 20 % slower. First finding: with all notes selected, a Piano Roll repaint took 63 ms instead of 5 ms; the selection is now worked out once per paint instead of once per key row, and it takes 5–7 ms (see [`PERFORMANCE.md`](./PERFORMANCE.md)). M6 features add their own bench scenarios as they are built: automation lanes, time-stretched clips, analysis meters, sidechain graph rebuilds.
- **Update mechanism (October 7, M6, first item):** **Help → Check for Updates** asks GitHub for Aerion's releases, and a quiet check runs 8 seconds after startup unless **Help → Check for Updates Automatically** is off. A newer release opens a window with its notes and Download and Install / Skip This Version / Later. The installer for the platform (`.exe` / `.dmg`) downloads to `AerionDAW/Updates` with a progress bar, and is checked against the size and SHA-256 digest GitHub lists for it. Then Aerion closes, asking to save as usual, and starts it (Windows) or opens it (macOS), or does so whenever it next closes. Alpha and beta builds are also offered pre-releases. A build knows the exact tag it was packaged from (`AERION_BUILD_VERSION` = `AERION_PACKAGE_VERSION`), so tags must be semantic versions that increase from release to release. Code in `Source/Updates/`; `UpdateTests` cover version order, release choice and the download check; `AerionTests --check-updates <version>` runs a real check and download (as 0.4.0 it fetched and verified the v0.5.0 installer). Not yet checked by hand in the running app, and not yet tried on macOS. Ships in v0.5.0; the withdrawn first 0.5.0 build had no updater, so its testers install the new one by hand once.

### September 2026

- **Save prompts acted on the wrong buttons (data loss):** JUCE numbers a three-button dialog's buttons 1, 2, 0, and the prompts assumed otherwise. "Save & Quit" quit without saving; in New / Open Project "Cancel" discarded the project and "Save" did nothing; Open Recent saved on "Discard"; Crash Recovery restored on "Discard". All prompts now go through `UI/Dialogs.h`, which names the answers and puts Cancel last (Escape cancels), and a test checks each button against JUCE's real alert window.
- **Plugin crash protection, first step (M5 stability, Windows):** a hosted plugin that crashes in `processBlock` (invalid memory access, division by zero, an escaped C++ exception) is caught by `PluginFaultMonitor`. That block is silenced, the plugin is bypassed and skipped, and a dialog says what happened; the rest of the session keeps playing. Turning the plugin back on lets it run again. Tracktion has no hook around the plugin call, so a small patch in `Patches/tracktion/` adds one, and MSVC builds use `/EHa` so catching a crash releases the lock JUCE holds while the plugin runs. Not yet covered: crashes in plugin editors, state save/load or instantiation, and macOS.
- **`UIComponents.h` split (M5):** the 9,500-line header is now one header per view under `Source/Views/` (Timeline, Mixer, Piano Roll, Inspector, Browser, Transport, menu bar, toolbar, dialogs), with `UIComponents.h` as an umbrella include. Code moved unchanged.

- **UI performance, phase 2 (M5):** the Timeline renders into a cached layer with the playhead on its own overlay; clip frames come from a nine-slice cache, waveforms from opaque whole-pixel images, icons and the fader cap from cached rasters, and background gradients draw as solid bands in software. **View → Lightweight UI** (Auto on weak machines) uses flat fills and lower animation rates. The splash now waits for the audio devices, so their half-second startup no longer freezes the main window. Also fixed: waveforms could be invisible with the software renderer. Numbers in [`PERFORMANCE.md`](./PERFORMANCE.md).

- **Unsaved-changes tracking (M5 stability):** a new, untouched project no longer shows `*My Song*` or asks to save on quit. The audio device finishing startup, plugin scans, and loading, creating or saving a project now send a status notification that refreshes the UI without marking the project changed. At the same time, edits made directly on the Edit (Timeline clip drags and trims), which never went through the engine's broadcast, now count through Tracktion's own change tracking. They had only looked tracked because every project was already marked changed at startup. The title bar picks these up within 200 ms.
- **Display-synced UI clock (M5 performance):** a `VBlankAttachment` on MainComponent replaces the separate 25 / 20 / 20 Hz component timers. The playhead moves every display frame; meters, transport readout and recording rows update at up to 30 Hz and keep running 1.5 s after stop so they decay to silence. The Inspector no longer repaints its fader 20 times a second while idle, the tooltip poll sleeps when the mouse is still, and the auto-save countdown uses real elapsed time.
- **Graphics engine setting (M5 performance):** **View → Graphics Engine** (Auto / Hardware Accelerated / Software), applied to every window through `GraphicsEngine::Policy`. Auto uses the software renderer up to 2560 × 1600 displays, because Direct2D measured 10× slower for the small repaints playback and editing are made of.
- **Timeline and Mixer repaint cost (M5 performance):** clip drags repaint only the clip (19–33 ms → 0.08–2.5 ms per mouse move); the playhead strip skips headers and clips outside it; the Mixer repaints only meters, fader caps and readouts during playback (5.7–7.3 ms → 2.4–3.3 ms per tick). All partial repaints are checked pixel for pixel by `AerionBench --verify`.
- **Performance tooling:** `AerionBench` measures Timeline and Mixer paint with both renderers, a clip-drag scenario, `--verify` pixel checks, `--snapshots` UI renders at 100 % / 150 % and (since October 5) `--scale` for any display scale; profiling builds log a message-thread stall watchdog. Baseline and results in [`PERFORMANCE.md`](./PERFORMANCE.md).
- **Unfreeze data loss and collapsed folders (PR #15):** unfreezing restores each clip's full saved state (trim, offset, fades) instead of the whole source file; collapsed folders hide their children in paint and scroll height, matching hit-testing.
- **Crash on Edit teardown:** track meters kept the last reference to each track's `LevelMeterPlugin` until after the Edit was destroyed or replaced, and its destructor then called into the dead Edit. Meters and thumbnails are now released first (quit, open project, new project).
- **Icon system and logo:** icons are fitted to their 24×24 viewBox instead of their drawn content (no more oversized or edge-touching glyphs) and tinted per state; transport icons follow their active state again; track toggles are letter buttons (M / S / R / A) in Timeline, Mixer and Inspector; the metronome icon is redrawn; the app uses a filter-free logo variant that shows on dark backgrounds.

## Current Build State
- **Platform**: Windows 11 (primary local dev — Visual Studio 2022, MSVC x64). macOS builds via CI/release workflow.
- **Presets**: `win-msvc-debug`, `win-msvc-release`, `win-msvc-debug-tests`, `win-msvc-profiling` (see root `CMakePresets.json` + `AerionDawCpp/Documentation/DEVELOPMENT.md`)
- **Engine**: Tracktion Engine v3.2 / JUCE 8, with small Aerion patches from `AerionDawCpp/Patches/` applied at configure time (also to a local `FETCHCONTENT_SOURCE_DIR_TRACKTION_ENGINE` checkout)
- **Build**: build the app and tests as targets, `cmake --build build --config Debug --target AerionDaw AerionTests --parallel`; a full solution build still fails in an unrelated Tracktion example target. After the embedded resource list changes, a parallel build can produce a damaged `AerionDawResources` object (`LNK1236`); rebuild that target on its own to fix it.
- **Moved clone**: a build folder records the clone's path. After moving the clone, configure a fresh build folder; the old one fails with "CMakeCache.txt directory is different".
- **Performance builds**: a separate Release build with `AERION_ENABLE_PROFILING=ON` (`build-profiling`) holds `AerionBench` and the profiling app; timings from Debug builds are not meaningful. `AerionBench` measures paint by default and the audio side with `--audio`.
- **CI**: both workflows are manual (`workflow_dispatch`) only. `build-test.yml` runs the Debug build, `AerionSmokeTests` and `AerionBench --verify` (at 100 % and at 125 % UI size) on Windows (MSVC/Ninja) and macOS (Clang/Ninja) — run it before merging a PR. `package-release.yml` (`release-package`) builds the Windows NSIS installer and macOS DMG, with optional self-signed Windows code signing, then publishes a GitHub Release with both attached. Installers are named after the tag; macOS Developer ID signing and notarization, and a `RELEASE_TOKEN` override for the release step, run when their secrets exist (see the release section of [`DEVELOPMENT.md`](./DEVELOPMENT.md)).
